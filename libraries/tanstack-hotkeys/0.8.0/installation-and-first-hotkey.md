# Installation and package choice

TanStack Hotkeys is a browser-oriented, framework-agnostic keyboard shortcut
library. The framework adapters re-export the core `@tanstack/hotkeys` API, so
an application normally installs either its adapter or the core package, not
both.

The product documentation calls the library alpha. The npm releases listed
here are ordinary non-prerelease versions, but the API can still change.

## Choose a package

| Environment | Package | Version at retrieval |
|---|---|---:|
| Vanilla JavaScript | `@tanstack/hotkeys` | `0.8.0` |
| React | `@tanstack/react-hotkeys` | `0.10.0` |
| Preact | `@tanstack/preact-hotkeys` | `0.10.0` |
| Solid | `@tanstack/solid-hotkeys` | `0.10.0` |
| Svelte | `@tanstack/svelte-hotkeys` | `0.10.0` |
| Vue | `@tanstack/vue-hotkeys` | `0.10.0` |
| Angular | `@tanstack/angular-hotkeys` | `0.10.0` |
| Lit | `@tanstack/lit-hotkeys` | `0.11.0` |

Do not infer the adapter version from the core version. All adapters depend on
core `0.8.0`, but their own package versions differ.

## Install

Use the package for the target framework. For example:

```sh
npm install @tanstack/hotkeys
```

```sh
npm install @tanstack/react-hotkeys
```

Equivalent package-manager commands may be generated by the official
installation page. The release documentation does not prescribe a project
creator, framework version, Node.js version, or package-manager version.

## Verification and setup gaps

The quick starts demonstrate observable shortcut behavior, such as pressing
Cmd+S or Ctrl+S, but do not provide a complete runnable project. They omit:

- project creation and prerequisites;
- exact filenames and entry-file wiring;
- `package.json` scripts;
- a development, test, or production build command;
- an official automated verification procedure.

Treat this bootstrap as partial. Supply the surrounding framework application
from that framework's versioned documentation before claiming a greenfield
project is reproducible.
